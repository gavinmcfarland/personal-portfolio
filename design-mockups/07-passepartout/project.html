plugma

A zero-config toolchain for building Figma plugins — with the hot reloading the platform never shipped.

The problem

A Figma plugin is two programs that cannot see each other. One runs in a sandbox with access to the document and no DOM; the other runs in an iframe with a DOM and no document. They communicate only by passing messages.

Nothing about that is unreasonable, but it means every plugin began the same way: most of a day assembling a bundler, a manifest, a message bridge, and a build step that inlines the UI into a single file. Every plugin author wrote the same four things, slightly differently.

The approach

Plugma puts all of it underneath. One command scaffolds a project, one develops it, one ships it — and the framework stays your choice rather than the tool's.

The part worth having is real hot module reloading. The UI is served from a dev server while you work and inlined at build time, so the sandbox half never notices the difference and figma.ui behaves identically in both. Edits appear without a rebuild and without losing plugin state, which is the thing that actually breaks concentration.

The result

Setup went from most of a day to a single command. It is still maintained, and it is the substrate under every plugin I have built since — which is the only endorsement of a tool that means anything.
