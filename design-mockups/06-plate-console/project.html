03problem

A Figma plugin is two programs that cannot see each other. One runs in a sandbox with access to the document and no DOM; the other runs in an iframe with the DOM and no document. They speak only by passing messages.

Neither half can be served from disk the way an ordinary web app can, so the UI has to be inlined into the built file. That single requirement is what breaks the development loop — inlining is a build step, and a build step means you are no longer editing, you are rebuilding and reloading by hand.

04approach

Plugma puts all of it underneath one command. One scaffolds, one develops, one ships, and the framework stays your choice.

The trick is where the UI lives. In development it is served from a dev server; at build time the same UI is inlined. The sandbox half never notices the difference, so hot module reloading works the way it does anywhere else.

The working notes live on a board rather than in a document, because the argument is spatial — two halves, a bridge, and what each side can reach.

06result

What it replaces took most of a day, every time. It now takes one command. Still maintained, and the substrate under every plugin I have built since.
