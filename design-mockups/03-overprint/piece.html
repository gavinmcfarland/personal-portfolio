03constraints what made it hard

two runtimes A plugin is two programs that cannot see each other. One sits in a sandbox with the document and no DOM; the other sits in an iframe with the DOM and no document.
no dev server Neither half can be served from disk the way an ordinary web app can. The UI has to be inlined into the built file.
messages only The halves speak by passing messages. Anything shared has to be serialisable, and anything typed has to be typed twice.

04build

Plugma puts all of that underneath a single command. One scaffolds, one develops, one ships, and the framework stays your choice — React, Svelte, Vue, or none.

The trick is where the UI lives. In development it is served from a dev server and pointed at by the manifest; at build time the same UI is inlined into the output. The sandbox half never notices the difference, so hot module reloading works the way it does anywhere else — edits appear without a rebuild, and without dropping the plugin state you were testing against.

05board fig. 1

The working notes live on a board rather than in a document, because the argument is spatial — two halves, a bridge, and what each side can reach.

06outcome

What it replaces took most of a day, every time. It now takes one command. Still maintained, and the substrate under every plugin I have built since.
