NAME

gavin — designer and engineer; builds the tool that was missing

SYNOPSIS

gavin [--design-systems] [--front-end] [--tooling] [problem ...]

DESCRIPTION

gavin operates in the gap between a design file and a shipped product. Given a problem, it will usually start by drawing the problem, and end by writing the code that solves it.

The most common failure mode it addresses is a team slowed by something nobody owns — a design system with no source of truth, a plugin toolchain that takes a day to configure. In these cases gavin builds the missing piece and documents it before exiting.

Exit status is zero when the work outlives the engagement.

OPTIONS

--design-systems
Tokens, components, and the governance that keeps them honest. Makes the design file and the codebase describe the same thing, and keeps them that way.
--front-end
Interface design carried through to production code. Implies --accessible and --fast; these cannot be disabled.
--tooling
CLIs, plugins and build steps. Turns a day of setup into a single command. See EXAMPLES.
