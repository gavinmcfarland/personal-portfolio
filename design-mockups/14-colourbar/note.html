Two programs, one plugin — a Figma plugin looks like one thing and behaves like two.

02 Description

One half of a plugin runs in a sandbox with access to the document and no DOM. The other runs in an iframe with a DOM and no document. They cannot call each other; they can only post messages, and every message is a string that used to be an object and will have to become one again.

The consequence nobody warns you about is that a plugin has no development loop. A change to the UI reloads the iframe, which drops the state that took nine clicks to reach, and the sandbox half restarts alongside it. So you make a change, you rebuild the state, you look at the change. Then you do it again.

Every worthwhile plugin tool is really a tool for narrowing that gap. Not for making the two halves into one — they cannot be — but for making the seam cheap to cross.

The message bridge is the obvious place to start, and the wrong one. Types across the bridge stop a rename in one half silently breaking the other, which is worth having, but it does not touch the loop. The loop needs the UI to be replaceable without the sandbox half restarting — which means serving it rather than bundling it, and then inlining it at build time so the shipped plugin has no dev server in it. 

// sandbox half — document access, no DOM
figma.ui.onmessage = (msg) => {
  if (msg.type === 'resize') {
    figma.ui.resize(msg.w, msg.h)
  }
}

Once the UI is served, the state survives the edit, and the plugin stops being a thing you rebuild in order to look at. That is the entire argument for plugma(1), and it took four versions to say it in one command.

in the margin

The sandbox half is not a worker. It is a QuickJS interpreter with the document bound into it, which is why nothing from Node is there.

Message payloads are structured-cloned, so a Date survives and a class instance does not.

Nine clicks is not a figure of speech; that is the table-creator test file.

Strip 01 — quad. The quietest of the six, which is the right choice beside running prose.
