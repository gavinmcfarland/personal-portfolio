How an engagement runs

Short loops, visible artefacts, no long silences. You should always be able to see what I am working on.

  1. Frame the problem

    A week of listening and reading the codebase. You get a written diagnosis and a scope — not a proposal deck.

  2. Draw it

    Design file first, at whatever fidelity the decision needs. Cheap to throw away is the entire point.

  3. Build it properly

    Production code in your repo, in your conventions, reviewed by your team as it lands.

  4. Hand it over

    Documentation and a walkthrough, so the work outlives the engagement. That is the measure of it.

About

I have spent fifteen years in the gap between design and engineering, and it turns out the gap is where most of the interesting problems live.

The pattern repeats: a team is slowed by something nobody owns. A design system with no source of truth. A plugin toolchain that takes a day to configure. So I build the missing tool. Plugma came out of that instinct and now underpins Figma plugins across the community.

Lately I write more code than pixels — mostly TypeScript, Svelte and Node — but I still start every project in a design file, because a problem you cannot draw is a problem you do not understand yet.
