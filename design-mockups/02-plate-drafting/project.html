03 problem

A Figma plugin is two programs that cannot see each other. One runs in a sandbox with access to the document; the other runs in an iframe with access to the DOM. They speak only by passing messages, and neither can be served from disk the way an ordinary web app can.

So every plugin begins by wiring a bundler, a manifest, a message bridge, and a build step that inlines the UI. Change one line and you rebuild and reload by hand. I had assembled that same toolchain enough times to stop pretending it was a one-off.

04 approach

Plugma hides that underneath. One command scaffolds, one develops, one ships, and the framework stays your choice.

The part worth having is real hot module reloading — edits appear without a rebuild and without losing plugin state. The UI is served from a dev server during development and inlined at build time, so the sandbox half never notices the difference.

05 shape fig. 1

The working notes for this project live on a board rather than in a document, because the argument is spatial — the two halves, the bridge between them, and what each one can reach.

06 result

The setup it replaces took most of a day. It now takes a command. Still maintained, and the substrate for every plugin I built after it.
