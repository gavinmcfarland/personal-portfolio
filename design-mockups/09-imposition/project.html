01

problem

A Figma plugin is two programs that cannot see each other. One runs in a sandbox with access to the document; the other runs in an iframe with access to the DOM. They speak only by passing messages, and neither can be served from disk the way an ordinary web app can.

So every plugin began with the same lost day: a bundler, a manifest, a message bridge, and a build step that inlines the UI. Change a line, rebuild, re-run, lose your state.

02

build log

2024-02 — the manifest is the seam

In development the manifest points at a dev server; at build time it points at the inlined output. Everything else followed from making that one file the only thing that changes between the two modes.

2024-05 — state-preserving reload

The sandbox half keeps running while the iframe half hot-reloads, so selection, document state and in-flight operations survive an edit. This is the feature the platform never shipped, and the reason the tool exists.

2024-09 — framework-agnostic templates

React, Svelte, Vue or none. The toolchain owns the bridge and the build; the framework stays your choice. One scaffolds, one develops, one ships.
