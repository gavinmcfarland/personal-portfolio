plugma

A zero-config toolchain for building Figma plugins — with the hot reloading the platform never shipped.

Problem

A Figma plugin is two programs that cannot see each other. One runs in a sandbox with access to the document; the other runs in an iframe with access to the DOM. They speak only by passing messages, and neither can be served from disk the way an ordinary web app can.

So every plugin begins by wiring a bundler, a manifest, a message bridge, and a build step that inlines the UI. Change one line and you rebuild and reload by hand. I had assembled that same toolchain enough times to stop pretending it was a one-off.

Approach

Plugma hides the two-program problem underneath. One command scaffolds, one develops, one ships. The framework is your choice, because the tool sits under the framework rather than beside it.

The part worth having is real hot module reloading. Edits appear without a rebuild and without losing plugin state, which turns interface work from a stop-start loop into something continuous.

Shape

plugin/ ├── manifest.json what Figma reads ├── src/ │ ├── main.ts sandbox — document access │ └── ui.tsx iframe — interface └── package.json

Two entry points, one manifest. Everything else is generated.

Result

The setup it replaces took most of a day. It now takes a command. Plugma is used by plugin developers across the Figma community and is still maintained.

It also became the substrate for everything after it — the later plugins listed on this site are all Plugma projects.
