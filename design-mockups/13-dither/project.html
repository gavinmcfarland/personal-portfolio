Name

plugma — build Figma plugins with a single command, and the hot reloading the platform never shipped.

Synopsis

$ plugma create [--react | --svelte | --vue]

$ plugma dev [--port <n>]

$ plugma build

Plate 1 — bloom · the loudest field in the set, spent here and nowhere else on this page

Description

A Figma plugin is two programs that cannot see each other. One runs in a sandbox with access to the document; the other runs in an iframe with access to the DOM. They speak only by passing messages, and neither can be served from disk the way an ordinary web app can.

So every plugin began with the same lost day: a bundler, a manifest, a message bridge, and a build step that inlines the UI. Change a line, rebuild, re-run, lose your state.

plugma puts all of that underneath one command. In development the UI is served from a dev server and pointed at by the manifest; at build time the same UI is inlined into the output. The sandbox half never notices the difference, so hot module reloading works the way it does anywhere else.

Example

// sandbox half — document access, no DOM figma.ui.onmessage = (msg) => { if (msg.type === 'resize') { figma.ui.resize(msg.w, msg.h) } }

History

2024-02 — the manifest is the seam

In development it points at a dev server; at build time at inlined output. It is the only file that differs between the two modes, and everything else followed from that.

2024-05 — state-preserving reload

The sandbox half keeps running while the iframe half hot-reloads, so selection and in-flight operations survive an edit. This is the feature the platform never shipped.

2024-09 — framework-agnostic templates

React, Svelte, Vue or none. The toolchain owns the bridge and the build; the framework stays your choice.
